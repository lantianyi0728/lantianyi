## 修复 ai-video.html「蒙版」问题
- 现象：用户截图反馈新页面内容像蒙了层纱。根因：styles.css 末尾的全局规则 `.section { opacity:.28; transform: translateY(24px) }` 依赖 app.js 的 IntersectionObserver 加 `.is-visible` 才淡入；ai-video.html 只挂了自己的 ai-video.js 没挂 app.js，栏目永远卡在半透明。
- 修复：ai-video.css 顶部加覆盖规则（`.section { opacity:1; transform:none }`，ai-video.css 在 styles.css 之后加载，同特异性后者胜出），另用纯 CSS `@keyframes ai-reveal` 做一次性淡入（prefers-reduced-motion: no-preference 才启用），不依赖 JS。
- 教训：**凡复用 styles.css 新建页面，必须处理 .section/.hero 的 opacity:.28 依赖**——要么挂 app.js，要么在页面自己的 CSS 里覆盖，否则内容半透明。

## 修复 ai-video.html「视频看不了」问题
- 现象：用户反馈视频无法播放。诊断（PowerShell Invoke-WebRequest 打预览服务器 URL）：mp4 都正常返回 200 + video/mp4，文件与服务器无问题。真正的坑是**交互设计**：文案写"想看整段的点封面"，但桌面端 click 没绑任何事件（只有 hover 播放），视频也没有原生 controls——用户点了没反应。
- 修复三件套：
  1. 5 个 video 全部加 `controls`——任何环境都有可点的播放键，不依赖 JS（保底）。
  2. ai-video.js 重写：hoverStarted 标记区分"悬停预览"和"用户手动播放"——只有悬停触发的播放才在 mouseleave 时暂停复位，用户点播放键看的不被打断；删掉触屏 click 分支（原生 controls 已处理，避免双 toggle 互相抵消）。
  3. CSS：删掉 .ai-hint 角标（和原生控制条重叠）；object-fit 从 cover 改 contain + 深色底 #141b18——AI 生成的竖版视频不会被裁掉头脚。
- 另一个学到的点：`<source>` 加载失败时 error 事件发生在 source 元素上而非 video 元素，两边都要监听。
- 教训：**"hover 自动播放"类交互必须配一个显式播放入口（原生 controls 最稳），文案别承诺没实现的点击行为。**
